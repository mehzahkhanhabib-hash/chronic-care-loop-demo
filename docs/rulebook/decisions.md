# Rulebook implementation decisions (demo)

The CCC Rulebook · T2D and Hypertension (20 November 2026) is the clinical source of truth and is used exactly as written: no threshold, score or trigger condition was changed or externally validated. The points below are the places where the rulebook text had to be mapped onto the columns that exist in the 250-member longitudinal file, or where the file and the text differ. Each is a row in a rule table, not code, so it can be changed by editing a CSV in `data/seed/rules/` and running `npm run reset`.

| # | Topic | Rulebook text | What the demo does | Where |
|---|---|---|---|---|
| D1 | HbA1c clinical band | "HbA1c (T2D only)" | The longitudinal extract scores the HbA1c band for every member with an HbA1c result (8 of 250 members are not in the T2D cohort but have a result). The demo follows the extract so the engine total equals `Total_risk_Score` for all 250 members; the engine reports both values side by side (`member_risk_result.extract_*`). | `risk_score_band.csv` RS-C-001…005 (`applies_feature` blank) |
| D2 | Comorbidity flags | Dyslipidaemia, BMI ≥ 30, smoking, CAD/MI, stroke/TIA, HF, PAD, retinopathy, neuropathy, foot ulcer, major amputation | The extract scores lifetime history, not only the last 12 months: `first_dyslipidemia_date`, `flag_obesity`, `flag_current_smoker_l12m`, `flag_ischemic_heart_disease`, `flag_stroke`, `flag_heart_failure`, `flag_dm_circulatory`, `flag_dm_eye`, `flag_dm_neuropathy`, `flag_dm_foot`, `flag_amputation`. These reproduce `Comorbid_complication_score` for 250/250 members. | `risk_score_band.csv` RS-M-009…019 |
| D3 | Utilisation | ED visits not admitted (0–3), unplanned admissions (1 → 3, ≥ 2 → 4) | The extract counts diabetes/hypertension-related utilisation: `l12m_ED_visits_DiaborHTNrelated`, `l12m_IP_admissions_DiaborHTNrelated` (reproduces `Utilization_score` 250/250). The all-cause columns `ed_visits_l12m` / `ip_admissions_l12m` remain available for the Trig4 post-discharge rule. | `risk_score_band.csv` RS-U-028…030 |
| D4 | Hypoglycaemia / DKA points | 2 and 3 points "per event" | The extract carries flags, not counts, so one event is assumed per flag. | RS-C-007, RS-C-008 |
| D5 | Kidney provisional score | CKD-stage fallback when both labs are missing | `ckd_stage_l12m` values `Stage 3a/3b/4/5` map to 1–4 points only when `Last_eGFR_Value` and `Last_UACR_Value` are both missing; `kidney_provisional = 1` is recorded. | RS-K-027a…d |
| D6 | Risk tier label in the file | Tier 1 Low … Tier 4 Very high | The file's `Risk_tier` label is reverse-numbered (`1. Very High` … `4. Low`). The engine derives the tier from the total with `rule_tier.csv` and keeps the file label as `extract_risk_tier` for reference. | `rule_tier.csv` |
| D7 | Trigger variant | Thresholds in §3 | Default `CCL_TRIGGER_VARIANT=rulebook`: thresholds evaluated from the raw columns (HbA1c ≥ 8, BP ≥ 140/90 or ≥ 130/80 with CKD/DM, eGFR < 60 or no eGFR/UACR in 12 months, PDC < 0.8 …). The file's own `Trig*_` flags (which fire HbA1c at 6.5%) are kept as `extract_flag` and can be used instead with `CCL_TRIGGER_VARIANT=extract`. | `rule_condition.csv`, `.env` |
| D8 | Individual HbA1c goal | "≥ individual goal (around 8%)" | 8% is used for every member. | `rule_condition.csv` Trig1 |
| D9 | ED visits in 90 days (Trig4) | "2 or more ED visits in 90 days" | The file has 12-month counts and the last ED date: approximated as `ed_visits_l12m ≥ 2` with the last ED visit within 90 days. | `rule_condition.csv` Trig4 |
| D10 | "Cannot tell" | — | A trigger whose inputs are missing (no usable BP, no HbA1c, no eGFR/UACR) is recorded as `cannot_tell` with the reason, never as fired. | `rule_condition.csv` rule_type cannot_tell |
| D11 | Plausibility (G0) | Impossible values are emptied | HbA1c outside 3–20, SBP 60–260, DBP 30–160, eGFR 1–200, BMI 10–80 are treated as missing before any rule reads them (e.g. a BMI of 170 or a BP of 1). | `rule-engine/features.js` PLAUSIBLE |
| D12 | Consent (G2) | Nothing below the consent card renders before consent | Consent is an event row (`consent_event`); the portal renders header, why-we-are-calling and the consent card only until the latest status is `granted`. Declined or withdrawn cancels open outreach. | `writeback.js` |
| D13 | Gap closure | Only claims evidence closes a gap | Nurse `done` → `Reported` + a "Verify in claims" follow-up; the gap moves to `Closed` only when the trigger stops firing in a later extract. | `rule_writeback.csv`, engine step 5 |
| D14 | Demo dates | — | `run_date` 2026-11-20 (the demo "today"), `as_of_date` 2026-10-31 (extract review date). Every "days since" in a rule is measured against the as-of date. | `.env`, `app_setting` |
| D15 | Names | The sources carry no names | Display names are deterministic pseudonyms generated from the masked id; the mask id is always shown beside them. | `importers/longitudinal.js` |
| D16 | Clinical sign-off | §8 says every trigger is a draft pending sign-off | Demo mode: all 14 triggers active. `rule_trigger.status` keeps the sign-off text; production would gate on it. | `rule_trigger.csv` |
